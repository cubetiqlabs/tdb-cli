## 2025-02-23 - Prevent secret leakage in serialized outputs
**Vulnerability:** When displaying configuration using `tdb config show` or `tdb config list --raw`, sensitive data like `AdminSecret` and API keys could be leaked. The original code was using shallow pointer dereferencing which could potentially mutate the original configuration or miss deeply nested secrets.
**Learning:** In Go, when serializing configurations containing nested maps or structures with secrets, it is vital to perform a deep copy or use dedicated data objects that inherently mask secrets. The original approach `display := *env.Config` and manual modification of `AdminSecret` failed to scrub nested tenant API keys and mutated the `AdminSecret` copy but could lead to issues.
**Prevention:** I have added a `MaskedClone()` method to the `Config` struct. This method deep copies the configuration and masks `AdminSecret` along with all deeply nested API keys within `Tenants[].Keys`. The `config show` and `config list --raw` commands now use `MaskedClone()` to safely prepare the structure for JSON/YAML serialization. Always prefer deep copy and mask approaches when dumping configuration data.
