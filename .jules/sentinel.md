## 2024-07-06 - Credential Leakage in Configuration Serialization
**Vulnerability:** API keys and other nested secrets inside the configuration structure were leaked in plaintext when executing `tdb config show`. The CLI command performed a shallow copy (`display := *env.Config`) before masking the top-level `AdminSecret` and serializing the output. Because slices and maps are reference types in Go, the nested `Tenants` map containing sensitive `APIKeyEntry` values was not copied, and the secrets remained unmasked during JSON/YAML serialization.
**Learning:** Shallow copying a struct in Go does not recursively copy pointers, maps, or slices. When serializing user configuration containing nested maps with secrets (e.g., using `yaml.Marshal` or `json.Marshal`), modifying the shallow copy to mask values does not automatically protect deeply nested secrets, leading to credential leakage in serialized outputs.
**Prevention:** Implement a deep copy mechanism, such as a `MaskedClone()` method, when preparing structures for display or serialization. The method should manually allocate new maps and slices, deep copy the values, and explicitly mask all secret fields before returning the fully sanitized, isolated copy.
