## 2025-01-01 - Optimizing Go String Concatenation and Table Rendering
**Learning:** To optimize string concatenation and table rendering in Go, pre-calculate the exact buffer capacity needed using `.Grow()` on a `strings.Builder` before writing. This avoids intermediate slice allocations, `strings.Join` overhead, and continuous buffer reallocations during heavily nested loops. Also, avoid using expensive O(N) functions like `runewidth.StringWidth()` to determine the capacity, as the calculation overhead will negate the allocation savings and cause performance regressions.
**Action:** When building strings iteratively or generating tables, always pre-calculate the maximum or exact required capacity using simple arithmetic (e.g., cell width counts) and call `builder.Grow(capacity)`.
## 2026-11-10 - Optimizing CLI table rendering
**Learning:** To optimize CLI table rendering in Go, cache the results of expensive operations like `runewidth.StringWidth` during the initial sizing traversal to reuse during the padding and rendering phase, rather than recalculating them. Also, use a simple loop with `WriteString` or `WriteByte` to a `strings.Builder` for repeated sequences (like table borders or padding) to avoid the intermediate string allocation overhead caused by `strings.Repeat`.
**Action:** When iterating over tabular data to calculate maximum column widths, store the individual cell widths in a parallel slice/array so they can be reused during the actual rendering phase. Avoid `strings.Repeat` for padding by writing individual characters directly to the pre-allocated `strings.Builder`.
