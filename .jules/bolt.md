## 2024-06-13 - Avoid reflection encoding when creating http requests for raw json bytes
**Learning:** Found an issue where the HTTP request builder (`newJSONRequest`) used `json.NewEncoder(buf).Encode(payload)` for *all* payloads. While fine for structs, the codebase frequently passes `jsonRaw` (which is `[]byte`). Passing raw bytes to `json.NewEncoder` triggers reflection and allocates a new `[]byte` containing the JSON-escaped string representation of those bytes, which completely misses the point of having raw bytes, and has significant memory and CPU overhead.
**Action:** When an HTTP client accepts a generic `interface{}` payload but the application often sends raw JSON bytes (e.g. from a CLI file read or byte array), always type-assert for the raw byte slice type (e.g. `jsonRaw`) and write it directly to the request body using `bytes.NewReader` to avoid reflection and double-encoding overhead.
